# 박힌 비즈의 밝은 림·잔 바닥·첫 POP

기준 커밋: `022926a`. 작업 브랜치: `codex/bead-rim-audio`.

## 수정한 파일과 이유

- `src/game/beads/BeadSprites.ts`: 사진/절차적 비즈의 기존 윤곽 마스크를 유지하면서 넓고 어두운 접촉 그림자를 좁은 접촉선으로 줄였다. 밀키한 실리콘 어깨 면과 좌상단의 얇은 반사를 분리했다. 비즈 회전을 역변환한 조명 방향을 32방향으로 양자화해 캐시한다. 비즈 아래쪽을 덮는 젤색은 줄였다.
- `src/game/Game.ts`: 박힌 비즈의 퍼진 그림자를 낮추고, 당겨 올라올 때 기존처럼 커지게 했다. 림에 비즈 회전을 전달한다. 기존 pointerdown 외에 정상 pointerup/native touchend에서도 오디오 unlock을 재시도한다. 입력·뽑기 판정은 변경하지 않았다.
- `src/game/collector/Collector.ts`: 내부 바닥을 유리잔 외곽 하단에서 `max(12px, 높이의 12%)`만큼 위로 옮겼다. 화면 회전 시 멈춘 비즈가 이전 화면 좌표에 남는 문제를 재현해, 잔의 새 바닥 기준으로 위치/크기를 함께 변환했다. sleep 및 충돌 정착 로직은 유지한다.
- `src/game/collector/JarAsset.ts`: 실제 내부 바닥과 어긋난 주석만 갱신했다.
- `src/game/audio/Sfx.ts`: 잠긴 AudioContext에서 첫 POP을 버리지 않고 최근 1회만 보관한다. running 전환 시 재생하고 즉시 비워 중복을 막는다. 음소거 시 보관음을 지우고 1.5초가 지난 소리는 재생하지 않는다. 짧은 무음 워밍업과 25ms 시작 여유를 두었다. 기존 음색/게인/설정 키는 그대로다.

사용자 스크린샷의 표시된 밝은 림은 참고용이다. 새 이미지를 생성하거나 원본 비즈/잔 에셋을 교체하지 않았다. 젤 메시·높이장·소켓·pull 물리·보상 확률·저장 스키마는 수정하지 않았다.

## 검증

macOS 데스크톱 Chrome의 모바일 크기 테스트다. iPhone/Android 실기기 검증이 아니다.

- 동일한 개발용 RNG/꽃 패드/5개 비즈 배치로 360/390/430px 전후 스크린샷을 남겼다. 운영 생성 규칙에는 시드를 추가하지 않았다.
- 일반 42개 비즈 패드에서도 사진 참과 절차적 비즈의 밝은 림을 확인했다. 가로 넘침, 실행 예외, 정상 에셋의 HTTP 오류 없음.
- 실제 브라우저 터치로 첫 비즈를 뽑으면서 오디오 resume 거부를 강제했다. 잠금 중 POP 보관=true/oscillator 시작=0 → 손 뗀 뒤 running/보관=false/oscillator 시작=3(한 POP의 구성음). AnalyserNode peak=0.1443, 미처리 Promise 거부=0.
- 음소거 중 보관하지 않음, 음소거 시 대기음 삭제, 오래된 POP 폐기, unlock을 반복해도 재생 중복 없음.
- 25개 비즈가 쌓인 뒤 정착=true. 추가 180프레임 동안 위치/회전이 완전히 동일했다. 390px 잔 하단과 최하단 비즈 사이 여유 약 15.67px. 화면 회전 후 최하단 비즈와 내부 바닥 오차 <0.001px, 잔 가로 경계 안에 유지.
- 새로고침 전후 localStorage 동일. 기존 진행/소리 설정 키와 데이터 구조 변경 없음.
- 별도 브라우저 컨텍스트에서 WebGL을 비활성화하고 비즈 이미지 요청을 실패시킨 뒤 실제 잡기→뽑기→수집 1회를 확인했다. Canvas 폴백 사용, 실행 예외 없음.

```sh
CI=true pnpm install --frozen-lockfile --ignore-scripts
pnpm --config.verifyDepsBeforeRun=false run typecheck
pnpm --config.verifyDepsBeforeRun=false run build
git diff --check
```

전부 통과. 빌드 54모듈, JS 309.36kB / gzip 100.23kB. 의존성/lockfile 변경 없음. 전체 프레임 시간이나 실기기 60fps는 이번 검사로 보장하지 않는다.

## 확인이 더 필요한 부분

- 브라우저 정책상 첫 터치가 오디오 활성화로 인정되지 않으면 첫 POP은 최초 손 떼기 직후 재생될 수 있다. 실제 iOS Safari/Android Chrome 스피커에서 첫 실행을 확인해야 한다. [WebKit의 사용자 활성화 이벤트 설명](https://webkit.org/blog/13862/the-user-activation-api/) 참조.
- 기존 제스처 소리의 음량은 조절하지 않았다. 이번 수정은 첫 POP 누락/재생 시점 처리다.
- 밝은 림의 취향 적합성은 사용자 실기기 화면에서 마지막 확인이 필요하다. 사진의 구워진 반사/그림자 자체는 수정하지 않았다.
