# 짧은 판 안에서 번갈아 만나는 촉감

## 후속 조정: 매 판 실 + 격판 소용돌이

- 첫 판은 구슬 줄 1개 + 컬러 실 2개, 이후 모든 패드는 컬러 실 1개 + 대표 촉감 1개다. 기존 일반 슬롯을 바꾸므로 총 뽑기 수와 보상은 늘지 않는다.
- 이후 대표 촉감은 `구슬 줄 → 소용돌이 → 무지개 줄 → 소용돌이 → 큰 알 줄 → 소용돌이 → 젤 막 → 소용돌이`로 반복한다. 따라서 소용돌이는 두 판 중 한 판이고, 나머지 재료도 네 번의 비소용돌이 판에 한 번씩 돌아온다.
- 개발/QA의 강제 `tactile` 쿼리는 비교가 쉽도록 지정한 재료 하나만 설치한다. 운영 진행에만 혼합 구성을 적용한다.

## 후속 조정: 첫 판의 실 + 첫 터치 오디오

- 첫 판은 기존 표면 목표 17개를 유지하면서 안전한 일반 슬롯을 구슬 줄 1개 + 떨어진 컬러 실 2개로 대체한다. 보물/왕비즈/아래층 숙주와 보상은 그대로이며 강제 촉감 QA 쿼리는 단일 재료를 유지한다.
- 이전 첫 완료음은 오디오가 잠긴 상태에서 1.5초 이상 손을 대고 있으면 폐기됐다. 새 촉감 단계음은 즉시 폐기됐고, 촉감 완료음의 고유 액센트도 누락됐다.
- Canvas의 네이티브 touchstart/touchend 캡처에서 오디오 해제를 시도한다. 아직 잠긴 경우 최신 소리 하나만 보류한다. 완료음은 현재 제스처 동안 보존하고 손을 뗀 후 1.5초, 단계음은 180ms 이내만 재생한다. 완료음이 단계음보다 우선하며 취소/음소거/게임 파기/리사이즈 시 버린다. 다음 제스처가 오래된 완료음을 되살리지 않는다.
- `node tests/audio-unlock.mjs`: 5초 지연 해제, 일반 + 6종 촉감 완료음, 중복 해제, 단계음, 취소/음소거/파기/오래된 소리 폐기 검사. 실제 오디오 출력 장치는 모킹하므로 실기기 청취 검증과 구분한다.
- `node tests/fibers.mjs`: 모든 11개 패드 × 30 시드 첫 판에서 구슬 줄 1 + 실 2, 총량/보물 유지 검사 추가.
- 희귀 패드 보상 구성과 랭킹은 이번 변경에 포함하지 않는다. 현재 비게임 등록 상태이며 토스 공식 게임 리더보드는 게임 카테고리만 지원한다.
- 검증 PASS: `pnpm build`, `node tests/audio-unlock.mjs`, `node tests/fibers.mjs`, `node tests/ad-policy.mjs`, `git diff --check`. 데스크톱 Chrome 터치 에뮬레이션의 360/390/430px에서 첫 실, 390px에서 첫 일반 비즈/구슬줄을 실제 touchStart/Move/End로 뽑아 각각 수집 1개와 오디오 running/음원 노드 재생 확인. 첫 판 표면 17개, 구슬줄 1 + 실 2, 가로 넘침/런타임 오류 없음. 실기기 청취와 토스 배포는 아직 안 했다.

## 후속 조정: 첫 판·마지막 큰 알·촉감별 피드백

이 절은 아래의 첫 판 일반 비즈만/위쪽 탭/아래 화살표 기록보다 최신이다.

- 첫 판 목표 비즈를 14개에서 17개로, 둘째 판은 18개에서 21개로, 이후 모든 패드는 기존 목표에 3개씩 추가했다. 총량 상한도 각각 3개 올렸다. 실제 배치 수는 실루엣과 비즈 간격에 따라 적을 수 있다.
- 첫 판에 추가 완료 요구 없이 기존 일반 비즈 한 개를 작은 알 3개와 마지막 큰 알이 달린 줄로 보여준다. 큰 알은 거의 끝까지 묻혀 있다가 점차 커지며, 병 안에서도 구분되도록 크기를 키웠다.
- 젤 막은 아래쪽에서 자유 방향으로 벗기던 모양/조작으로 돌리고 화살표를 없앴다. 회전 젤의 방향 화살표도 제거했다.
- 실, 구슬 줄, 무지개 줄, 회전 젤, 막에 각각 짧고 서로 다른 단계 소리를 넣었다. 녹음된 기본 POP이 재생될 때도 마지막 순간의 짧은 재질별 음색이 남는다. 마지막 큰 알은 묵직한 퐁 소리와 강한 완료 햅틱, 젤 반동을 사용한다. 연속 루프음이나 반복 탭음은 추가하지 않았다.
- 토스 안에서는 네이티브 햅틱 호출을 우선하고, 실패할 때만 브라우저 진동을 시도한다. 실제 갤럭시·아이폰의 진동 세기와 설정은 실기기에서 아직 검증하지 못했다.

## 후속 피드백: 줄 변형 + 돌려 풀기 + 방향성 있는 막

이 절은 아래 최초 버전의 3종 순환을 대체한다. 첫 판 이후 `chain → rainbow → swirl → charm → fiber → peel`의 6종 순환이다. 추가 뽑기·장비·보상 확률·영구 저장 필드 없이 기존 안전한 일반 슬롯을 사용한다.

- `rainbow`: 190 기준 단위, 크기가 다른 7알의 연속 당김. 작은 간격으로 풀리는 감각.
- `charm`: 174 기준 단위, 작은 3알과 마지막 큰 알. 마지막 큰 알은 원래 슬롯의 비즈 종류/색/회전을 쓰고 추출 87%까지 묻혀 있다. 마지막에 기존 비즈의 POP 소리를 사용하며 줄 전체가 병에 들어간다.
- `swirl`: 젤 끝을 잡고 시계/반시계 어느 쪽이든 1¼회전. 반대 방향 왕복은 진척을 중복 생성하지 않고, 정지/중앙 통과/직선 바깥 당김으로 완료되지 않는다. 부분적으로 풀고 다시 잡을 수 있다. 풀린 뒤 원래 비즈가 기존 소켓과 수집 경로를 사용한다.
- `peel`: 위쪽의 홈이 있는 흰 탭과 아래 화살표. 아래 방향 이동만 추출되며 옆/위 당김은 진행되지 않는다. 실제 14% 벗기기 전에는 처음 잡았다는 이유만으로 안내를 없애지 않는다. 접힌 면은 위에서 아래로 이동한다.

공통 코드: `Fiber.ts` 입력과 단계, `Tactile.ts` 순환/선택, `TactileRenderer.ts` 캐시 스프라이트와 Canvas 표현, `Game.ts` 입력/피드백/비행, `Collector.ts` 표시 분기만 수정. 기존 일반 Pull/Spring2/Collector 물리와 광고·프로모션은 그대로다. 이전 검증 결과는 아래 날짜 기록이고 후속 버전 검증은 말미에 기록한다.

## 구현

첫 판은 기존 비즈만 사용한다. 완료 이력으로 두 번째 판부터 구슬 줄, 젤 막, 컬러 실을 순환한다. 재접속이나 컬렉션 선택만으로 종류를 건너뛰지 않는다. 각 판은 한 종류의 촉감에 집중한다.

- **구슬 줄**: 이미 배치된 일반 표면 비즈 하나를 연결된 작은 알 다섯 개로 표현한다. 148 기준 단위의 당김 거리 안에서 다섯 단계의 저항과 풀림을 준다. 시간·속도·실패 조건 없이 충분히 당기면 나온다. 각 중간 단계는 한 번만 짧은 POP/진동을 내고 최종 카운트는 한 번만 증가한다. 빠르게 당기면 지나친 소리 중첩을 피하도록 입력 샘플당 한 번만 재생한다. 병에서는 작은 목걸이 모양으로 모인다.
- **젤 막**: 가장 큰 안전한 일반 슬롯의 기존 비즈 위에 밀키 민트색 얇은 막을 덮는다. 끝을 잡고 94 기준 단위만큼 당기는 동안 접힌 경계가 이동하고 비즈가 드러난다. 부분적으로 벗기고 놓아도 그대로 다시 잡는다. 완전히 벗기면 원래 비즈가 자동으로 병에 들어간다. 희귀 보상을 새로 만들거나 원래 비즈의 종류·색을 바꾸지 않는다.
- **컬러 실**: 기존의 긴 손 뽑기 유지. 최대 세 가닥이고 핀셋은 없다.

모든 재료는 기존 일반 비즈를 대체한다. 추가 슬롯·추가 완료 요구·장비 구매·확률 변경은 없다. 왕비즈, 보물, 아래층 비즈 및 숙주는 보호한다. 첫 노출 때 한 줄 안내만 나오며 UI 메뉴를 추가하지 않는다.

## 코드

- `fibers/Tactile.ts`: 판별 순서와 안전한 대체 슬롯 선택.
- `fibers/TactileRenderer.ts`: 기존 비즈 에셋을 캐시해 구슬 줄을 그리고, Canvas로 투명 막과 접힌 경계를 렌더링. 새로운 이미지 다운로드 없음.
- `fibers/Fiber.ts`: 기존 부분 추출 상태를 재사용하면서 구슬 줄의 거리 단계와 막의 펼쳐진 상태를 추가.
- `Game.ts`: 입력, 제한된 단계 피드백, 기존 완료 이벤트 연결. 젤 막의 비즈는 기존 스프라이트와 소켓·착지음을 사용.
- `Collector.ts`: 구슬 줄의 그림만 추가. 충돌 및 sleep 물리는 유지.

기존 비즈의 Pull/Spring2, 광고 정책, 프로모션 조건, 저장 형식은 수정하지 않았다. 새로고침 시 진행 중 판을 다시 생성하는 기존 정책도 유지한다.

## 테스트 및 미리보기

`pnpm build`, `node tests/fibers.mjs`. 단위 검사는 실 990개 배치와 새로운 두 재료 660개 배치에서 총량/보물/지오메트리/놓기/재잡기/단조 증가/정지 시 진행 없음/느린 당김 완료를 검사한다.

`output/playwright/tactile-play.js`는 운영 빌드의 `/ssok/`에서 격리된 저장소와 실제 터치 이벤트로 360·390·430px 조작을 검사한다. 두 신기능 각각 390px에서 마지막 항목으로 완료→다음 판에서 다른 촉감→새로고침 저장 유지까지 검사한다. 운영 빌드의 강제 미리보기 쿼리는 무시되어야 한다.

정적 미리보기: `pnpm exec vite build --mode tactile-preview --outDir output/tactile-preview`. 이 출력은 테스트 링크 전용이며 일반 운영/AIT 출력과 다르다. 이 모드의 쿼리로 촉감을 직접 선택할 수 있다. 토스 SDK 실광고·실보상·실기기 진동을 검증한 것으로 해석하지 않는다.

main, GitHub Pages, 토스 AIT에는 아직 반영하지 않았다. 실제 안드로이드/iOS 기기 검증 및 성능 측정은 별도이며 60fps를 보장하지 않는다.
