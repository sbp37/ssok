# 2026-09-23 완성도 개선 / 로컬 검증

기준 커밋 `4ff7018`, 작업 브랜치 `codex/polish-80`. 목표는 새 기능이나 새 게임이 아니라 현재 쏙의 재질·연속 동작·한 판 마무리 완성도를 높이는 것. 80점은 주관적인 제품 평가이며 자동 테스트의 점수가 아니다. 이 문서는 로컬 작업 기록이며 운영 배포 확인서가 아니다.

## 수정 범위

- `gel/Gel.ts`: 반투명 윗면 아래 겹치던 어두운 면/반복 테두리를 줄이고 밀키한 색과 얇은 가장자리로 정돈. 실제 패드 외곽과 구멍에서의 거리로 320px 시각용 높이장을 만들고 미분 전에 평활화. 리본의 방사형 X자 음영을 제거. Canvas 폴백은 공통 정점의 두 삼각형을 투명 버퍼에 coverage 합성해 셀 경계의 이중 알파/격자 현상을 제거.
- `Game.ts`, `beads/Bead.ts`: 잡힌 비즈·젤 목·비행 시작점이 같은 보이는 중심과 배율을 사용. 당기는 동안 겹치던 소켓을 한 번만 그리며 비즈 실루엣을 유지. 목은 오목한 허리와 넓은 부착면, 뿌리의 부드러운 알파 연결. 작은 재사용 버퍼이며 매 프레임 새 캔버스를 만들지 않음. 기존 완료 시점에 수집통의 짧은 반사 4개 추가.
- `beads/BeadSprites.ts`: 자개 조각의 넓은 진주광·옆면 음영. 행성 모양 띠는 추가하지 않음. 스프라이트 캐시 용량 제한, 당길 때 배율마다 새 그림자/립 마스크를 만들지 않음.
- `util/BoundedCache.ts`, `tests/sprite-cache.mjs`: 읽기 시 최근 사용 순서 갱신하는 크기 제한 캐시와 10,000회 삽입 등 회귀 검사.
- `ui/App.tsx`, `ui/styles.css`: 완료 문구와 패드 이름을 패드 아래에 표시. 입력/진행을 막는 대기나 새로운 보상 없음.

물리 스프링, 뽑힘 임계값/속도 조건, 패드 모양/비즈 생성/확률, 수집통 충돌과 sleep, 광고·프로모션·저장 스키마·효과음은 변경하지 않았다. 새로운 이미지/의존성/엔진을 추가하지 않았다. 기존 WebP를 그대로 사용한다.

## 검증 근거

`output/playwright/`의 스크립트는 별도 QA 브라우저에서만 실행한다. 비교 시드 8080과 저장 데이터 초기화는 이 스크립트에만 있으며 앱 코드에 넣지 않았다.

- `polish80-capture.js`: 360/390/430px × 하트/꽃/리본. 같은 seed의 전후 비즈 개수와 좌표·반경·회전 체크섬 일치. `polish80-before-*-*.png`, `polish80-after-*-*.png`.
- `polish80-play.js`: 3개 너비에서 실제 포인터로 왕비즈 중도 놓기/복원 → 5개 POP → 병 정착 → 완료 한 번 → 다음 패드. 비행 시작 위치 차이 0. 설정·컬렉션 광고 숨김과 닫은 뒤 복구, 완료 저장 유지 확인. 왕비즈를 주입한 테스트 배치는 QA 전용.
- `polish80-full.js`: 프로덕션 `/ssok/` 경로, 자연 생성된 하트 34개를 실제 포인터로 끝까지 뽑기. 33개 병 도착+숨은 보물 1개, 완료 1회, 비행 중 완료 없음, 병 상단 잘림 없음, 다음 패드와 새로고침 저장 확인. 비즈 에셋 19개 로드, HTTP 오류/페이지 오류 없음.
- `polish80-king.js`: 실제 생성된 숨은 왕비즈는 덮인 동안 잡히지 않음 → 윗 비즈 제거 → 왕비즈 등장 → 약 107px 늘어남 → 병 도착 확인. 별도 확률이나 성공 조건 변경 없음.
- `polish80-fallback.js`: WebGL 강제 차단과 비즈 WebP 전부 실패를 동시에 적용. 360/390/430px에서 실제 POP/수집, 기존 완료 10회 유지, 화면 회전 뒤 정규화 좌표·반경 오차 1e-15 미만, reduced motion, 가로 넘침/페이지 오류 없음. 기능 검사와 별도로 스크린샷의 격자 현상도 육안 검사.
- 11개 기본 패드 전환 렌더와 유한 좌표 검사. `polish80-all-*.png`는 전환 중 페이드 시점이 포함될 수 있어 재질 비교의 기준 이미지는 `before/after`를 사용.

## 성능 / 제한

macOS 데스크톱 Chrome 153, DPR 2, 높이 844px, 너비 360/390/430. 실제 안드로이드/iOS 또는 토스 웹뷰 실기기 결과가 아니다.

동일 QA 스크립트 기준 변경 전 rAF 간격 중앙값 16.5~16.8ms, P95 약 17.8~19.1ms. 변경 후 반복 측정 중앙값 16.6~16.8ms. 베이스 재생성 warm 중앙값은 전 1.1~3.8ms, 후 0.9~2.2ms. 변경 후 P95는 동시 브라우저/빌드 부하가 있는 측정에서 18.4~56.4ms로 흔들렸다. 따라서 60fps 보장이나 프레임 성능 향상을 주장하지 않는다. rAF는 프레임 간격이며 순수 렌더 CPU 시간이 아니다.

실기기 햅틱/스피커 체감, 토스 실제 광고 fill, 실제 프로모션 지급은 이번 변경에서 검증하지 않았다. 기존 동작을 보존했고 광고 정책 테스트는 별도 실행한다. 팔레트/광택 개선에도 실시간 3D 굴절이나 물리 기반 실리콘 산란을 구현한 것은 아니다. 공간 배치/콘텐츠 루프는 유지했다.

실행 명령: `pnpm typecheck`, `pnpm build`, `node tests/sprite-cache.mjs`, `node tests/ad-policy.mjs`, `git diff --check`. 최종 결과는 작업 응답과 해당 실행 출력을 함께 확인한다.

## 최종 로컬 판정

위 명령 모두 통과. 최종 빌드 JS 390.42kB / gzip 126.10kB, CSS 10.83kB / gzip 3.17kB. 최종 소스로 3개 모바일 너비의 5개 뽑기·중도 놓기·완료·다음 판·시트 광고 숨김·저장 검사 재통과. 최종 `/ssok/` 빌드의 34개 전체 판도 재통과했고, POP 위치 연속성 오차는 34개 모두 0, 완료 후 병 33개+보물 1개, 수집통 상단 잘림 0, 페이지/HTTP 오류 0이었다. WebGL/사진 에셋 동시 실패 시에도 당기는 중과 정지 상태 양쪽에서 격자 없는 화면을 확인했다.

QA 중 비교 캡처 세션의 자동 localStorage 초기화가 저장 검사에도 적용된 적이 있어, 플레이 검사를 초기화 훅 없는 새 격리 컨텍스트로 분리한 뒤 1→2→3회 완료 저장을 재확인했다. 앱의 저장 코드를 변경한 문제가 아니다.

판정: **로컬 제품 QA PASS**. 이 기록은 실기기 성능·소리·진동 또는 토스 운영 노출을 보증하지 않는다. 커밋/푸시/머지/토스 제출은 하지 않았다.
