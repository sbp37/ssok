## 현재 들어 있는 최신 기능

- 길게 당기는 컬러 실, 구슬이 줄줄이 나오는 줄, 무지개 줄, 마지막에 큰 알이 달린 줄, 돌려 풀어내는 소용돌이, 벗기는 젤 막.
- 재료별 소리/햅틱/단계별 추출 반응, 일부 뽑고 놓았다가 다시 잡기, 수집통 이동.
- 첫 판: 큰 알이 달린 줄 1개 + 컬러 실 2개. 이후 매 판 컬러 실 1개 + 대표 촉감 1개. 소용돌이는 격판이며 나머지 재료를 번갈아 배치한다.
- 첫 판 표면 목표 17/전체 상한 23, 두 번째 21/27, 이후 전체 상한 31. 모양·배치 여유에 따라 실제 수는 적을 수 있다. 새로운 재료는 일반 슬롯을 대체한다.
- 첫 뽑기 음원의 지연 오디오 해제 처리, Toss 네이티브 햅틱 우선, 시작 로딩/소리 안내/패드 이름.
- 키로의 렌더 모듈 분리, CI/테스트, 프로모션 모드 오타 차단, `?perf=1`, 완료 후 공유를 통합했다. 구슬줄/실 비행과 반동이 빠지지 않게 `render/Flight.ts` 등을 최신 코드와 조정했다.

## 요청 1: 지금 버전의 재미와 개선 방향

코드를 확인하고 가능한 환경에서 직접 플레이한 뒤 첫 판의 재미, 재료별 차별성, 반복 피로, 다음 판/내일 다시 만지고 싶은 이유를 평가해 줘. 예전 평가에서 바뀌어야 할 점도 알려 줘. 측정한 사실과 추측은 구분하고, 실행하지 못한 테스트는 했다고 쓰지 말아 줘.

## 요청 2: 새로운 비즈/촉감 요소를 창의적으로 제안

사용자는 네가 새로운 비즈나 뽑을 거리를 추가해 주길 원해. 구체적인 종류나 생김새는 지정하지 않을게. 현재 앱과 잘 어울리면서 단순 색 교체에 그치지 않는 발견/촉감/재미를 자유롭게 생각해 줘.

우선 네가 가장 좋다고 생각하는 아이디어와 이유, 조작의 직관성, 구현 비용, 모바일 성능 위험을 제안해 줘. 선택 후 구현할 수 있게 해 줘. 종류를 미리 정해 둔 요구는 없으며 지금 든 예시들을 또 복제할 필요도 없어. 별도 화폐·출석·미션·강제 타이머는 추가하지 말아 줘.

## 요청 3: 수익화를 위한 광고 방향 의견

**현재 코드는 일반 전면광고 2판 간격이다. 아래 매 판 방안은 아직 구현하지 않았으며 먼저 의견을 요청한다.**

사용자는 수익화를 강화하고 싶고 다음 방안을 선호한다.

1. 첫 판은 광고 없이 즉시 시작.
2. 첫 판을 완료하고 다음 패드를 누르는 순간부터, 매 판 전환에 전면광고. 별도의 90초 시간 제한은 두지 않는 방안.
3. 희귀 패드는 기존 선택형 보상광고 유지. 보상광고와 전면광고를 연달아 겹치지 않음.
4. 마지막 비즈 POP/완료 연출은 끝까지 보여 준 뒤 전환. 뽑는 도중 광고 없음.
5. 광고 실패·물량 없음이면 다음 판으로 정상 진행.
6. 하단 배너는 플레이 화면만, 설정/컬렉션에서는 숨김.

짧아진 실제 판 길이에서 매 판 전면광고가 적절한지 솔직한 의견을 줘. 대안이 있다면 수익과 이탈을 함께 비교하고, 사용자당 수익/실노출률/다음 판 진행률/다음 날 재방문 등 판단에 필요한 측정 계획을 제안해 줘. 임의의 수익 수치는 만들지 말고 플랫폼 정책은 최신 공식 자료로 확인해 줘. 이번 단계에서 광고 정책을 조용히 바꾸지 말아 줘.

## 안전 조건과 검증

- 기존 저장·수집·보상 확률·프로모션을 유지. 실/줄/소용돌이/막과 첫 소리 수정을 누락하거나 예전 버전으로 되돌리지 않기.
- 기존 물리 구조, 60Hz 스프링 서브스텝, Collector sleep을 유지. 손맛 조정은 근거와 범위를 먼저 설명.
- `pnpm install --frozen-lockfile`, `pnpm check`, `pnpm build`. 개발 서버의 `?pad=flower&tactile=chain` / `rainbow` / `charm` / `fiber` / `swirl` / `peel`은 비교용이며 일반 운영 빌드에서는 강제 쿼리를 무시한다.
- 현재 타입 검사/7개 테스트/TEST 및 LIVE 빌드는 통과했다. 통합 전후 15,462개 Canvas 명령 비교도 통과했으나 이는 화면 픽셀 검사나 모바일 성능 측정이 아니다.
- 통합 시점에는 로컬 브라우저 실행이 차단돼 새 버전의 360/390/430 화면 및 토스 실기기 확인은 못 했다. 첫 소리/햅틱/공유/실광고는 기기 확인이 필요하다.
- `pnpm toss:build`는 TEST 프로모션, `pnpm toss:build:live`는 실제 지급 코드다. 리뷰/개발 중 실지급 호출이나 운영 배포를 하지 말 것.
- main 직접 푸시/운영 배포/자동 머지는 하지 말고 작업 브랜치에서 진행. 관련 없는 PR을 합치지 않기.

먼저 최신 기준 확인 → 실제 평가 → 새 비즈 아이디어와 광고 의견 순서로 보고해 줘.
