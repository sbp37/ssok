# 패드 전환 광고 설계

## 기본 규칙

- 처음 두 판(완료 2회 전)은 전면광고가 없다(`FREE_PADS = 2`). 그 뒤 일반 패드 전환이 전면광고 후보가 되며, **직전 전체화면 광고(전면·보상형 모두)로부터 75초 이상**(`MIN_GAP_MS`) 지났을 때만 노출한다. 한 판이 1분 안팎이라 평소엔 거의 매 판이지만, 보상광고 직후나 빠른 연속 판에서 광고가 연달아 뜨지 않는다.
- 광고 준비 실패·no-fill·표시 예외는 해당 전환을 소비하지 않아 다음 일반 NEXT에서 다시 시도한다.
- 보상형 버튼은 **보상광고가 실제로 로드돼 있을 때만** 보인다(1초마다 다시 확인). 누를 수 없는 광고 버튼이나 눌러도 아무것도 안 되는 버튼은 만들지 않는다.
- 보상형은 사용자가 완료 화면의 광고 문 하나(`ads/Offers.ts`)를 선택할 때만. 패드마다 딱 하나만 제안한다: 다음이 변종이면 **잡기**, 이번 패드에 보물이 없었으면 **한 번 더 파기**(보너스 미니패드), 보물함에 빈칸이 있으면 홀수 판에 **심기**(다음 패드 보물 지정), 그 외 **고르기**(다음 패드 셋 중 선택). 보상 획득 확인 시에만 지급. 취소/실패 시 **그 화면에 그대로 머물고** 짧은 안내(`광고를 불러오지 못했어` / `끝까지 보면 받을 수 있어`)를 띄운다 — 사용자가 고른 문을 말없이 다른 문으로 바꾸지 않는다. 실패한 같은 전환에 전면광고를 추가하지 않는다(`AdPolicy.waive`).
- 보너스 미니패드는 진행·완료·프로모션 지급에 세지 않는다(`PadProgress`를 건드리지 않음). 따라서 보너스 패드 뒤의 NEXT는 전면광고 간격상 이미 소비된 전환이라 전면광고 없이 열린다 — 완료 1회당 광고 1회 원칙은 유지되고, 그 1회가 전면형에서 보상형으로 바뀐다.
- 플레이 중 68% 시점의 `광고 보고 살짝 보기`(처음 보는 보물이 묻혀 있을 때만, 패드당 1회, **처음 두 판에는 없음**)는 추가 보상형이다. 보상을 받으면 묻힌 보물이 **그 판이 끝날 때까지** 또렷이 보인다(예전 2.4초는 광고 값을 못 했다). 왕비즈는 보물이 아니므로 이 문을 열지 않는다. 이 광고도 75초 간격 계산에 들어가므로 바로 뒤 NEXT 전면광고는 건너뛴다. 광고를 못 불러오면 버튼을 없애지 않고, 다음 광고가 로드되면 다시 보인다.
- 어느 문이 제안·선택·획득됐는지 `ssok.adstats.v1`에 로컬로 센다(식별자·전송 없음). **제안은 버튼이 실제로 화면에 보인 순간에만** 센다(광고가 안 불러와져 숨은 문은 제안이 아니다). 살짝 보기도 제안을 센다.
- **보상은 `userEarnedReward` 순간 플레이어 것이다.** 그 순간 재시작해도 남는 부분을 먼저 저장한다: 심기는 다음 패드에 보물을 묻고, 잡기는 변종을 "잡음"으로 표시하고(`nextCaught`), 한 번 더 파기는 보너스 보물을 그때 정해 `bonusTreasure`로 남긴다. 그래서 광고가 끝내 안 닫혀 앱을 껐다 켜도(10/8 AdMob 장애) 변종이 열리고, 보너스 판을 같은 보물로 파고, 심은 보물이 묻혀 있다. 판 도중 종료 후 재시작은 같은 패드에 **같은 보물**을 다시 묻는다(`currentHidden`). 보물을 **뽑은 순간** 두 값 모두 비운다 – 재시작으로 같은 보물을 또 얻거나(광고 한 번에 보물 하나) 다시 굴릴 수 없다.
- 변종을 한 번도 못 본 플레이어는 4번째 패드가 반드시 희귀 변종이다(`FIRST_VARIANT_PAD`). 잡은 변종은 보물 확정·레어 비즈 집중·왕비즈로 광고값을 한다(`VARIANT_PERKS`).
- 희귀 패드의 보상형 광고는 그 전환의 전면광고를 대체한다. 그 다음 일반 패드 전환부터 다시 전면광고 후보가 된다(75초 간격 적용).
- 완료 화면에서 앱을 껐다 켜면 지나가던 희귀 변종이 아니라 **일반 버전**이 열린다(재접속으로 광고 문을 우회하지 않음). 변종 몫으로 굴린 보물도 따라가지 않는다.
- **광고 재생 중에는 게임 소리를 멈추고**(`sfx.pause("ad")`) 닫히면 다시 켠다. 앱이 백그라운드로 가도 같은 방식으로 멈춘다. 토스 광고 정책 요구사항.
- **광고 ID**: 실제 지급 번들(`pnpm toss:build:live`, `VITE_PROMOTION_MODE=live`)에서만 `ait.v2.live.*` 광고 그룹을 쓰고, 그 외 모든 빌드(개발·QA·AIT 테스트 푸시)는 토스 테스트 그룹(`ait-ad-test-interstitial-id` / `ait-ad-test-rewarded-id` / `ait-ad-test-banner-id`)을 쓴다. 실제 광고 ID로 테스트하는 것은 토스 광고 정책 위반이다. 빌드 로그 `[ssok] promotion + ad mode:`로 확인한다.
- **배너**: 하단 전용 영역. 로딩 화면이나 시트가 덮는 동안에는 붙이지 않는다. 버튼과 배너 사이에 30px 여백을 둔다(실수 클릭 방지). no-fill·초기화 실패에도 **자리(높이)는 그대로** 두고 비워 둔다 – 접으면 판 도중에 패드 크기가 바뀌어 당기던 손가락이 끊긴다. no-fill은 다음 패드에서, 초기화 실패는 다음 패드마다 한 번씩 최대 3번 다시 시도한다. 배너를 주기적으로 갈아 끼우지 않는다(정책상 인위적 갱신 금지).
- 완료 연출(별 1.15초) 이후 1.2초에 NEXT를 열고 사용자 클릭으로만 실행. 마지막 POP 순간에 자동 표시하지 않는다.
- 설정/컬렉션/앱 시작에는 호출하지 않는다. 향후 발견 패드 선택은 이 NEXT 경로와 분리한다.
- 광고 준비가 안 됐으면 즉시 진행. 실행 예외도 진행. 중복 클릭은 잠그며 한 번만 패드를 연다.

## 현재 구현과 SDK 경계

`createAdProvider()`는 토스 광고 API(`loadFullScreenAd`/`showFullScreenAd`)를 지원하는 환경이면 `TossAdProvider`를, 아니면 `MockAdProvider`를 쓴다.

- **TossAdProvider**: 앱 시작 때 전면·보상형 광고를 한 개씩 미리 로드하고, 노출이 끝나면 다음 광고를 다시 로드한다. 로드가 30초 안에 답하지 않으면 포기하고(`LOAD_TIMEOUT_MS`, 늦게 온 응답은 무시) 재시도한다. 재시도 간격은 15초 → 30초 → 60초 → 이후 2분(`RETRY_MS`)이고, 완료 화면의 1초 확인(ready)이 이 간격을 건너뛰지 않는다. ready는 사전 로딩 상태를 동기 반환하며 NEXT에서 광고 로딩을 기다리지 않는다. show는 `dismissed` 뒤 완료하고, 보상형은 `userEarnedReward` 이벤트를 받은 경우에만 rewarded를 반환한다 – **그 뒤에 오류·`failedToShow`가 와도 rewarded**다. `dismissed`가 안 오면(10/8 장애) 광고가 뜬 뒤 1초가 지나 **페이지에 닿은 터치**를 닫힘으로 본다(광고가 덮고 있으면 터치가 페이지에 오지 않는다). `failedToShow`/예외는 unavailable로 즉시 진행한다.
- **MockAdProvider**(일반 브라우저·로컬·QA 빌드): 전면광고는 항상 unavailable로 즉시 진행하며 실제 광고 화면/노출/매출은 없다. 희귀 변종은 모의 보상 성공으로 열린다. 모의 성공도 테스트용 빈도 제한에는 반영되지만 실제 노출 지표로 집계하면 안 된다.
- **NoAdProvider**(실배포 빌드인데 광고 미지원 구버전 토스): 문을 하나도 보여 주지 않는다. 실배포에서 모의 광고로 공짜 보상을 주지 않는다.

아직 실기기에서 확인하지 않은 것: 광고 도중 사운드/게임 입력 정지·복구, 백그라운드 복귀, 동의/연령 정책, 실제 fill률과 매출.

모든 제공자에 걸리는 60초 watchdog은 **광고가 화면에 뜨기 전(`show`/`impression` 이벤트 전)까지만** 동작한다. 뜨지 않은 광고는 abort를 전달하고 게임을 진행시킨다. 일단 뜬 광고는 닫힐(`dismissed`) 때까지 기다린다 — 긴 보상광고를 끝까지 본 사람이 보상을 잃지 않게. 어댑터는 abort 시 광고가 뒤늦게 뜨지 않도록 취소하고 이미 열린 오버레이도 정리해야 한다. 이 계약을 지원하지 않는 SDK는 그대로 연결하지 않는다. 60초는 광고 길이 약속이 아니다.

별도 저장 키 `ssok.ads.v1`: lastAdCompleted, lastAdAt. 진행/보물 저장은 수정하지 않는다. 저장 차단 시 메모리 정책으로 계속 동작한다.

## 운영 실험 (아직 수집하지 않음)

SDK 연결 이후 consent를 고려해 NEXT 요청, 정책 스킵 사유, 실제 노출/닫힘/보상, 다음 패드 시작을 구분한다. 모의 성공을 실제 노출로 세지 않는다. 광고 직후 이탈·다음 판 시작률·재방문·사용자당 실제 수익을 함께 비교해 매판 정책의 이탈 영향을 점검한다. 수익 개선은 아직 검증되지 않았다.

검증: `pnpm test`(`tests/ad-policy.mjs` 포함), `pnpm build`. PR마다 CI가 같은 명령을 실행한다.

광고 문 선택 규칙·4번째 패드 변종 보장·변종 특전·보물 가중치는 `tests/offers.mjs`에서 검사한다. 현재의 **처음 두 판 무광고 + 75초 간격** 정책, no-fill/오류 복구, 로드 시간 초과·재시도 간격, 보상 뒤 오류·닫힘 누락은 `tests/ad-policy.mjs`(가짜 브리지·가짜 시계)에서, 재시작해도 남는 보상은 `tests/restart.mjs`에서 검사한다. 실기기/실광고/매출은 별도 검증이 필요하다.

수정 파일: `ads/AdPolicy.ts` 정책/제공자, `ui/App.tsx` NEXT 연결·연타 잠금·연출 대기, `Game.ts`와 `pads/progress.ts`의 이전 보상형 전용 연결 제거, `tests/ad-policy.mjs` 정책 회귀 검사, README 및 이 문서. 젤·비즈·저장 진행·보상 확률은 변경하지 않았다.
