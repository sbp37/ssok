# 패드 전환 광고 설계

## 기본 규칙

- 최초 생애 첫 패드 완료 후 NEXT는 전면광고 면제. 기존 진행의 totalCompleted를 읽기만 한다.
- 두 번째 완료부터 일반 NEXT / 희귀 변종의 ‘그냥 다음’에서 전면광고 후보.
- 직전 광고 종료 후 최소 120초, 이번 접속 시작 후 최소 120초를 모두 만족해야 한다. 탭을 켜둔 시간도 포함하는 초기 정책이며 실제 활동 시간 기준은 아니다.
- 보상형은 사용자가 ‘광고 보고 잡기’를 선택할 때만. 보상 획득 확인 시 희귀 변종, 취소/실패 시 일반 패드. 실패한 같은 전환에 전면광고를 추가하지 않는다.
- 보상형을 시청하고 닫았다면 보상 획득 여부와 무관하게 다음 일반 전환 1회도 면제. 120초 간격도 다시 시작한다.
- 완료 연출(별 1.15초) 이후 1.2초에 NEXT를 열고 사용자 클릭으로만 실행. 마지막 POP 순간에 자동 표시하지 않는다.
- 설정/컬렉션/앱 시작에는 호출하지 않는다. 향후 발견 패드 선택은 이 NEXT 경로와 분리한다.
- 광고 준비가 안 됐으면 즉시 진행. 실행 예외도 진행. 중복 클릭은 잠그며 한 번만 패드를 연다.

## 현재 구현과 SDK 경계

`AdPolicy`의 기본 제공자는 모의 구현이다. 전면광고는 항상 unavailable로 즉시 진행하며 실제 광고 화면/노출/매출은 없다. 희귀 변종은 기존 모의 보상 성공 동작을 유지한다. 모의 성공도 테스트용 빈도 제한에는 반영되지만 실제 노출 지표로 집계하면 안 된다.

토스 미니앱의 실제 광고 API를 연결할 때 `AdProvider`만 교체한다. ready는 사전 로딩 상태를 동기 반환하며 NEXT에서 광고 로딩을 기다리지 않는다. show는 닫힘 뒤 완료하고 토스 광고 API의 보상 획득 콜백만 rewarded로 반환한다. 광고 도중 사운드/게임 입력 정지·복구, 백그라운드 복귀, 동의/연령 정책, 노출 콜백 및 광고 오버레이 종료는 어댑터 구현과 실기기 검증이 필요하다. 현재 코드만으로 실광고 운영 준비가 완료된 것은 아니다.

모의/향후 제공자 보호용 60초 watchdog은 abort를 전달하고 게임을 진행시킨다. 어댑터는 abort 시 광고가 뒤늦게 뜨지 않도록 취소하고 이미 열린 오버레이도 정리해야 한다. 이 계약을 지원하지 않는 SDK는 그대로 연결하지 않는다. 60초는 광고 길이 약속이 아니다.

별도 저장 키 `ssok.ads.v1`: lastAdAt, skipNext. 진행/보물 저장은 수정하지 않는다. 저장 차단 시 메모리 정책으로 계속 동작한다. 새로고침은 기존 간격을 단축하지 않고 접속 유예를 다시 시작한다. 사용자 시계/로컬 저장은 조작 가능하며 보안·과금 판정용이 아니다.

## 운영 실험 (아직 수집하지 않음)

SDK 연결 이후 consent를 고려해 NEXT 요청, 정책 스킵 사유, 실제 노출/닫힘/보상, 다음 패드 시작을 구분한다. 모의 성공을 실제 노출로 세지 않는다. 광고 직후 이탈·다음 판 시작률·재방문·사용자당 실제 수익을 함께 비교하여 120초를 조절한다. 수익 개선은 아직 검증되지 않았다.

검증: `node tests/ad-policy.mjs`, `pnpm --config.verifyDepsBeforeRun=false run build`.

데스크톱 Chrome 실제 NEXT 버튼 검사: 첫 완료 광고 호출 0회 → 두 번째 완료 1회 → 간격 내 다음 완료는 추가 호출 없음 → 시간 경과 후 모의 실행 예외에도 4번째 패드 전환 성공. 360/390/430px 가로 넘침 없음, 실행 오류 없음. 실기기/실광고/매출 검증은 수행하지 않았다.

수정 파일: `ads/AdPolicy.ts` 정책/제공자, `ui/App.tsx` NEXT 연결·연타 잠금·연출 대기, `Game.ts`와 `pads/progress.ts`의 이전 보상형 전용 연결 제거, `tests/ad-policy.mjs` 정책 회귀 검사, README 및 이 문서. 젤·비즈·저장 진행·보상 확률은 변경하지 않았다.
