# 마지막 알 마무리·입력 점검

기준: `418f724`, 작업 브랜치: `codex/round-settle`.

## 변경

- `Game.ts`: 마지막 POP의 중복 반동을 한 번으로 정리. 기본 POP 반동에 마지막 알만 ×1.22를 적용한다. 모든 비행이 끝나고 기존 수집통의 `settled`가 120ms 유지된 뒤 완료음/완료 이벤트를 한 번 보낸다. 완료 저장은 기존처럼 POP 즉시 처리한다.
- `Game.ts`: 패드 밖 터치의 탭 소리, 아래 비즈가 올라오기 전 잡히는 문제, 큰 숨은 비즈의 보이는 크기보다 넓은 판정을 수정했다. 리사이즈 때 `slotR`도 비즈 반경과 같은 비율로 조정한다.
- `Pointer.ts`: 취소/캡처 상실과 정상 손 떼기를 구분해 취소 입력으로 탭 소리를 내지 않는다.
- `App.tsx`: 병 정착 후 기존 완료 문구를 표시하고 650ms 뒤 다음 버튼을 보여준다. 전환 시 이전 완료 UI 타이머를 취소한다.
- `Gel.ts`: 320×320 원본 조명 결과를 실제 형상/구멍/크기/두께/색으로 키를 구성해 최대 6장 보관한다. 색/계산식/해상도는 동일하다. RGBA 픽셀 저장량 약 2.4MiB, 브라우저 자체 오버헤드는 별도다.

`pull.ts`, `spring.ts`, `Collector.ts`, `Sfx.ts`, `BeadTypes.ts`, `PadTypes.ts`, 보상/저장 스키마와 에셋은 수정하지 않았다.

## 확인한 동작

데스크톱 Chrome 152, macOS Intel, DPR 1. 실기기 테스트가 아니다.

- 360/390/430px 실제 브라우저 화면, 가로 넘침 없음.
- 브라우저 터치 입력 2개: 젤 누르기와 비즈 잡기가 동시에 유지됨(젤 손가락 2, 당김 1). 두 손가락 필수 규칙은 추가하지 않았다.
- 실제 포인터 당김으로 테스트 패드 5알을 모두 뽑아 병에 수집했다.
- 마지막 POP → 마지막 병 진입 약 0.78초 → 병 정착/완료까지 추가 약 0.95초인 실행을 기록했다. 고정 지연값이 아니라 실제 비행/수집통 상태에 따라 달라진다.
- 느린 이전 비즈가 아직 날아갈 때 완료하지 않음, 마지막 보물 획득/완료 1회, 완료 중 패드 변경 시 이전 이벤트 취소.
- 패드 밖 탭/취소 탭 무음, 빈 젤 정상 탭 유지, 420ms 대기 중 아래 비즈 잡기 차단, 올라온 비즈 정상 잡기.
- 큰 숨은 비즈의 중심/터치 여유는 잡히고, 그림에서 떨어진 지점은 잡히지 않음. 이웃 비즈 정상 선택. 화면 회전 후 `slotR / radius` 유지.
- 배포 빌드를 `/ssok/`에서 실행: 새로고침 후 완료 이력/미리 저장한 다음 패드 유지, 다음 버튼으로 새 패드 열기.
- WebGL 비활성화와 비즈 WebP 요청 실패를 동시에 강제: Canvas/절차적 비즈 폴백에서 실행/당김 유지. 의도적으로 차단한 이미지 요청 오류 외 JS 런타임 예외 없음.

## 성능·시각 검증

- 조명 원본과 수정 결과를 11개 패드 × 360/390/430px에서 RGBA 비교했다. 33조건 모두 차이 0. 최종 버전은 미세 계산 최적화도 제외하고 원본 계산식을 그대로 사용한다.
- 같은 환경의 최초 조사에서 원본 조명 생성은 꽃 약 68~181ms, 리본 39~82ms, 도넛 96~153ms(각 12회)였다. 기기 부하/JIT에 따라 편차가 크다.
- 일치하는 결과가 캐시에 남은 경우 조회/복원은 약 0~0.1ms였다. 0ms는 브라우저 타이머의 측정 해상도 미만이라는 뜻이다.
- 첫 생성, 캐시에서 밀려난 형상, 새로운 크기/색은 원래 계산 비용이 남는다. 전체 패드 전환이나 모바일 60fps를 보장하는 수치가 아니다.
- 꽃 끝 저항 0.82 / 중심 1.1, 리본 매듭 1.28 / 날개 0.88. 같은 작은 비즈 기준 이미 차이가 있어 수치를 더 키우지 않았다. 실제 손의 선호도 검증은 별도다.

## 실행 명령

```sh
CI=true pnpm install --frozen-lockfile --ignore-scripts
pnpm --config.verifyDepsBeforeRun=false run typecheck
pnpm --config.verifyDepsBeforeRun=false run build
git diff --check
```

고정 의존성 설치와 타입 검사/빌드 통과. 로컬 pnpm의 자동 재설치 검사만 끈 실행 옵션이며 프로젝트 설정/lockfile은 변경하지 않았다. 설치 시 esbuild 후처리 스크립트는 실행하지 않았으며 설치된 플랫폼 바이너리로 Vite 빌드를 확인했다.

## 남은 확인 사항

- 연결된 Android 기기가 없어 첫 소리, 스피커/이어폰에서 creak/tap/rub의 체감 음량, 실제 진동은 확인하지 못했다. 게인을 임의 조정하지 않았다.
- `pull.ts`는 큰 비즈라도 오래/멀리 당긴 경우 `minSpeed × 0.45`로 빠지는 예외가 있다. 요청 설명의 “minSpeed 이상 필수”와 차이가 있지만 의도 확인 전 유지했다.
- 정확히 패드 로컬 원점의 `Gel.inside(0, 0)`는 구멍 없는 패드도 false다(기존 `d > holeRadius` 조건). 단일 점의 기존 경계 문제로 이번 범위에서 수정하지 않았다.
- 시드 공유, 컬렉션 재입장, 해금 순서 변경, 새 보상/UI/소리는 추가하지 않았다.
