# 비즈 선명도와 박힌 깊이 보정

기준: 작업 브랜치 `codex/bead-rim-audio`의 `1b3f81e`. 2026-09-13 사용자 최종 승인으로 앞선 림/잔 바닥/첫 POP 수정과 함께 main에 반영하는 후속 수정이다.

## 범위

- `BeadSprites.ts`: 재염색 비즈의 과도한 흰색 screen 보정을 줄여 원본의 몸체/반사 대비를 살린다. 거의 흰색인 진주·레진은 별도 소량 보정해 회색으로 치우치지 않게 한다. 원본 에셋, 색상 데이터, 종류/확률은 그대로다.
- 같은 파일의 윤곽 메니스커스: 밝은 면을 좌상단에 집중하고 둘레 전체의 흰 띠를 줄인다. 사용자 추가 참고 이미지처럼 비즈와 바깥 림 사이에 음영이 있는 안쪽 벽을 둔다. 실제 윤곽보다 1.2~2.4px 넓고, 화면 아래로 최대 1.7px 더 이어지는 자리이며 비즈 내부는 마스크로 제외한다. 밝은 림은 이 자리의 외곽에 놓는다.
- 아래쪽 전체에 젤색을 덮던 그라데이션 대신, 실제 윤곽을 따르는 좁은 앞쪽 가림을 만든다. 가림 폭은 반경의 16%, 1.2~2.8 CSS px 범위이며 하단에서만 겹친다. 반대편에는 노출된 중심을 건드리지 않는 짧은 안쪽 접촉 그림자를 추가한다. 초기 시안의 과한 하단 가림(38%)은 최종에 사용하지 않는다.
- 회전된 비즈도 광원은 좌상단, 앞쪽 가림은 화면 아래 방향을 유지한다. 결과는 기존 스프라이트 캐시에 보관하고, 기존 `(1-lift)`로 뽑힐수록 사라진다.
- `Game.ts`: 박힌 비즈 전체 아래의 퍼진 그림자는 낮추고, 들어 올릴 때 다시 진해지도록 한다. 입체감은 바닥 위 그림자 대신 홈의 안쪽 벽/앞쪽 겹침에서 만든다.

젤 메시, 소켓의 치유, 숨은 비즈의 깊이/흐림, 히트 영역, 뽑기 물리, 저장/보상, 소리, 수집통은 이번 후속 작업에서 바꾸지 않았다. 새 이미지/라이브러리는 추가하지 않았다.

## 확인 방법

데스크톱 Chrome의 360/390/430px 화면에서 개발용 고정 RNG 꽃 패드를 비교한다. 시드는 브라우저 검사에서만 설정하며 운영 생성 코드에는 추가하지 않는다. 390px/DPR 2에서는 실제 포인터로 잡기→당김→POP→병 정착을 확인하고 새로고침 전후 localStorage를 비교한다. 실기기 검증이나 모바일 60fps 보장이 아니다.

로컬 증거는 작업공간 `output/playwright/rim-audio/`에 있다.

- `clarity-before-*.png`: 이번 선명도 작업 전.
- `clarity-after-*.png`: 몸체/림 선명도 보정.
- `clarity-depth-after-*.png`: 앞쪽 가림을 늘렸던 중간 시안.
- `clarity-reference-after-*.png`: 사용자 추가 참고 이미지의 안쪽 벽을 반영한 최종 화면.
- `clarity-dpr2-*.png`: 실제 게임의 잡기/뽑기/수집 상태.

검증 명령: `pnpm --config.verifyDepsBeforeRun=false run typecheck`, `pnpm --config.verifyDepsBeforeRun=false run build`, `git diff --check`. 의존성 및 lockfile 변경 없음.

최종 검사: 위 명령 통과, 빌드 54모듈/JS 310.76kB(gzip 100.69kB). 360/390/430px 가로 넘침 없음. DPR 2에서 포인터 당김→POP→수집 1개/병 정착/소켓 1개, 새로고침 후 저장 동일, 실행 예외 및 정상 HTTP 오류 없음. 별도 컨텍스트에서 WebGL 비활성화와 비즈 이미지 실패를 강제한 Canvas 폴백에서도 1개 뽑기/수집 및 실행 예외 없음을 확인했다. 최초 main 반영은 안전 검토로 보류했으며, 이후 사용자의 명시적 최종 반영 승인을 받았다.
